# 人物剪纸编排：从真实轮廓到整集有声成片

2026-11-15。沿用剧情驱动 Vox 的判断顺序，把人物从实际图片中提取为透明图层，与旧纸、布料、门帘、镜面和代码道具一起编排。先确定观众此刻要看懂什么，再决定哪些层出现、谁遮住谁、何时停稳。

这些是本篇结果。下一篇不固定197镜、18类布局或35层轮廓，也不把“45帧后可停稳”套到别的组件。机器扫描和抽检不等于逐帧人工观看。

本页公开方法、通用工具、空白模板和不带私人素材的演示工程。生产用正文、演员图、配音、完整字幕和成片仍在原项目；页面中的轮廓示意不是演员素材。

## 02｜先把剧情写成视觉任务

完整阅读，锁定本篇人物唯一ID、关系、服装、年代、地点和用户最新选定的参考。新封面替换旧参考时，同步修改人物表、Muse参考文件和工程入口，避免两套演员同时成为权威。

每镜先写五件事：原文锚点、观众获得的新信息、首先看的对象、随后看的对象、此刻禁止提前出现的内容。再决定全景、独立人物、接触人物组、物件局部或代码信息装置。

同一图的有效派生可以是：关系全景 → 施压者 → 被听者 → 手中物件 → 信息揭示 → 后来的回访。变体要改变关注点。换一个边框、字幕换字和持续慢推不单独算新分镜。

形状从剧情中找：帘幕承担遮挡，三面镜承担反射，纸样承担选择与修改，衣服夹层承担秘密，工具留下的痕迹承担前后呼应。下一篇应找自己的视觉线索，不能机械复制这套量尺和缝线。

## 03｜先算需要什么，再给Muse任务

90分钟先以24–30张图、最多2段视频为预算参考，按本篇不可替代的事实调整。定妆、独立背景和额外首尾帧都计入；同图裁切和alpha派生记录父图，不另算生成，但也不能把新生图伪装成派生。

优先准备适合后续使用的素材：主要人物轮廓和手部清楚、与背景有可辨边界；主场景保留可站人的空间；复杂接触动作有专门图；视频首帧尽量复用已有图。不要为每镜单独生成一张。

Muse生成摄影素材，工程负责剪纸排版。全局电影风格、人物身份和每镜服装动作在执行前合成独立提示词；封面的固定站位不复制给所有剧情图。可用[素材任务模板](templates/asset-task.json)。

## 04｜按实际内容接入素材

查看所有图片和视频，读取真实尺寸、帧率、时长、声音和动作。生成端的“通过”记录不代替接入检查。差异写成“原计划 → 实际内容 → 接入决定”，与原素材一起保留。

| 实际差异 | 编排方法 |
| --- | --- |
| 视频只有亲近和镜头推进，没有拍到计划的缝针动作 | 只把它当作相处的动态段落；动作细节用相符静图或代码示意承接 |
| 照片的衣扣数多于原文 | 避开展示完整错误数量，使用局部和独立的精确计数示意 |
| 原图肢体被桌面或画框挡住 | 保留原遮挡、加有依据的前景，或留在照片裁口内；不补出不存在的腿和手 |
| 缺少车内、后台等新地点的摄影素材 | 用有依据的衣料或物件局部过渡，明确是编辑表达，不把旧房间改名冒充新现场 |

视频按实测时长原速单播。照片适合有限平移、前后层级、换焦与遮挡；真实转身、拥抱和手部接触必须由实际姿态或视频支持。

## 05｜提取真实轮廓，并保留接触关系

Mac示例使用Apple Vision前景实例遮罩：[VisionMasks.swift](tools/VisionMasks.swift)。它提取前景实例，不保证每一例都只是一名人物；可能把接触的两人、衣台或桌子分成同一组。每层必须检查透明通道和真实边界。

```sh
xcrun swiftc tools/VisionMasks.swift -o vision-masks
./vision-masks source-png mask-output IMG_A IMG_B
python3 -m pip install Pillow
python3 tools/trim_masks.py --source source-png --masks mask-output --output derived-v1
```

输入使用PNG；名称不带扩展名。Swift输出原尺寸透明图与实例清单。后处理从原图重新复制RGB，只取遮罩的alpha，再按实际边界裁切，输出父图哈希、边界和图层尺寸。原图不变，不为抠图重新生成演员。

| 轮廓状况 | 实施决定 |
| --- | --- |
| 独立完整人物 | 可独立改变层级、位置和有限角度 |
| 两人牵手、扶持、接吻 | 保持接触组为整体，不拆成两张纸再扭曲拼接 |
| 半身或原本被遮挡 | 放在可信的纸边、桌边或照片窗口后，保留其可见范围 |
| 遮罩包含大块桌面、反射或破碎肢体 | 回到原图裁口，或人工修轮廓并重新检查；不直接当成合格独立人物 |

每层记录parent_asset_id、原图哈希、人物组ID、bbox、服装/时空状态与验收结果，参考[轮廓登记模板](templates/cutout-layer.json)。35层不是35张新演员图；同图中多个前景实例也不等于多个可随意重组的人。

## 06｜构图与动作怎样落地

[通用组件](starter/src/PaperStage.tsx)提供纸纹、异形照片裁口、透明人物层、语义揭示与原速视频窗口。它们执行已经写好的镜头决定，不负责自动挑剧情。

| 镜头目的 | 可用构图 | 动作与停顿 |
| --- | --- | --- |
| 看懂关系 | 人物大小、前后遮挡、空间距离 | 短入场后停稳，主次由本镜决定 |
| 首次出现的人物 | 门帘/门框遮挡与局部人物层 | 到原文出现点才揭开；不能把完整封面从0秒摆出 |
| 看懂动作细节 | 保留原姿态的人物组＋物件局部 | 全景建立后切细节，放大时保持比例并检查脸和手 |
| 阅读证据 | 撕边纸、夹层、手机、姓名与短文字 | 按声音逐项揭示，完成后停稳，不提前给结论 |
| 表现自主选择 | 放开人物周围空间，保留本人署名与物件 | 由她的选择引出下一层，避免只让旁人移动她 |

纸纹、阴影、纸样、量尺、缝线、手机、文件和招牌由代码完成。底板色彩与形状跟着本篇章法走。形状变化有原因，不每隔几秒随机换一种皮肤。

字幕放在独立安全区。裁切保持原宽高比，侧边Quote避开脸和手。半身层的平直底边应有可信的遮挡，不能让残缺的人体悬空；接触人物组不要拉伸。原速视频放入明确的绝对定位窗口，不在底下无限循环。

## 07｜配音决定揭示时间

先检查原声首尾、章节顺序和完整时长，再将声学识别词元映射回原文。字幕保留原文名字；小缺口可局部插值，长缺口要回听。文本匹配率不是逐词人工听校率，也不是TTS原生字级时码。

镜头开始与事实出现是两个时间。为金额、人物身份、衣物破口、账本和计数分别登记source_phrase、source_char_start、actual_reveal_frame。照片会提前泄露时，先裁掉或遮住对应区域，而非只延迟旁边的文字。

帧区间采用左闭右开：start_frame计入，end_frame_exclusive不计入。检查全片镜头覆盖、字幕有效区间和视频原速窗口。用[逐镜模板](templates/shot-plan.json)交接；不能把估算时码写成已经对齐。

## 08｜先做可播放工程与代表片

数据保存原文锚点、叙事任务、父素材、轮廓、ROI、遮挡、动作窗口和揭示帧号；组件只执行这些决定。不要通过镜头编号取模来挑布局，也不要求用齐18类或65类。

先检查各类构图、重要揭示前后、两段视频及末段，再做有声代表片。本次检查197镜代表帧，加视频/门控帧共213张；两分钟样片完成3600帧解码与异常纯色筛查。下一篇需要自己的检查集。

工程public里的交付媒体应为实文件。本次发现跨目录音频软链接在导出打包时会丢失，因此在冻结渲染工程前复制原图、视频与原声，核对SHA256。[materialize_public.py](tools/materialize_public.py)提供有边界的复制工具；图片名、真实扩展名与实际格式一致。

素材返回后不重跑旧的Muse任务生成脚本覆盖交付清单。工程状态应明确区分“待素材”“可播放工程”“样片”“整集成片”。独立的另一份预览工程按自己的入口播放，不混用其声音、帧率或时间表。

## 09｜精确画面复用必须按源码重审

先沿用[渲染队列与声音门禁](../workflow/tools/render.py)生成当前源版本的计划。新工程的状态键要覆盖全部可见时间依赖：镜头、有限运动、Quote、事件阈值、字幕选择、视频、遮罩和全局里程碑。

本篇源码的有限动作最长43帧，适配器保守逐帧采集镜头前45帧，Quote附近20帧、事件附近40帧及整个视频区间；这些值只对应本篇源码，不能变成下一篇默认的截帧规则。

验证顺序：普通连续PNG组内像素比较 → 独立稀疏截图比较 → 运动/揭示/视频逐帧覆盖 → 章节与全集同一全局帧等价 → 同质量编码短测。源文件、runtime和适配器都固定哈希；变化后新建revision，不能只刷新哈希跳过验证。

本次18类静止布局组内像素相同，静止与视频短测编码SSIM均1.0。整集输出130943帧，实际截图18279次，输出仍为30fps。队列含启动、编码、拼接、AAC合轨和声音验收约751.6秒；不含之前的适配/短测/bundle，以及之后的视觉与最终解码检查。这不是不同画面的截图fps，也不保证下一篇达到同样速度。

## 10｜声音、画面与交付一起验收

H.264画面配默认AAC-LC音轨。MP3原声作为输入保留，交付MP4时转AAC-LC/48kHz；复用本库已有[声音门禁](../workflow/tools/audio_delivery.py)，不为新风格另写一条绕过检查的总装路径。转码后检查时长、完整解码、真实音量与首中尾波形，压缩包哈希不适用。

所有切片和最终MP4完整解码；低分辨率全帧扫描只筛候选。查看每片首中尾、接缝与角色ROI连续帧；字幕变化不能冒充人物运动。最后在实际播放器取消静音播放，记录播放器状态与检查范围。

本次77切片和全片130943帧扫描无异常纯色候选，231张首中尾图和32张视频运动样本已检查；最终文件全片音画解码通过，并在播放器中非静音播放。结果不等于对所有视觉问题的绝对保证。

交付整集MP4、SRT、完整工程、接入决定与QA报告；工程ZIP中媒体为实文件，解压后安装依赖即可运行。下一篇复用这里的判断与组件，重新编排人物、剧情、底板和素材缺口。
